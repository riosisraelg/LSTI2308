Parte 4: Configuración y análisis de RAID en Linux

Práctica en Linux — Configuración de RAID

Objetivo

Configurar y analizar:

RAID 0 (Striping)

RAID 1 (Mirroring)

Usando mdadm en Linux.

Shape Requisitos previos

Instalar herramienta RAID

sudo apt install mdadm

(o en RedHat/CentOS:)

sudo yum install mdadm

Shape

Ver discos disponibles

lsblk

Ejemplo usado en práctica:

/dev/sdb

/dev/sdc

(Discos vacíos agregados a la máquina virtual).

Shape

Shape

RAID 0 — Striping

Característica

Divide datos entre discos.

Mayor velocidad.

Sin tolerancia a fallos.

Creación del arreglo RAID 0

sudo mdadm --create --verbose /dev/md0 \ --level=0 --raid-devices=2 /dev/sdb /dev/sdc

Verificar:

cat /proc/mdstat

Formateo del sistema de archivos

sudo mkfs.ext4 /dev/md0

Montaje

sudo mkdir /mnt/raid0

sudo mount /dev/md0 /mnt/raid0

Verificar:

df -h

Prueba de funcionamiento

sudo touch /mnt/raid0/prueba.txt

ls /mnt/raid0

Si aparece el archivo → funciona correctamente.

RAID 1 — Mirroring

Característica

Copia exacta de datos en ambos discos.

Alta tolerancia a fallos.

Menor velocidad que RAID 0.

Creación del arreglo RAID 1

sudo mdadm --create --verbose /dev/md1 \

--level=1 --raid-devices=2 /dev/sdb /dev/sdc

Verificar sincronización:

cat /proc/mdstat

Formateo

sudo mkfs.ext4 /dev/md1

Montaje

sudo mkdir /mnt/raid1

sudo mount /dev/md1 /mnt/raid1

Prueba de funcionamiento

sudo touch /mnt/raid1/prueba.txt

ls /mnt/raid1

Prueba de tolerancia a fallos

Simular fallo de disco:

sudo mdadm /dev/md1 --fail /dev/sdb

sudo mdadm /dev/md1 --remove /dev/sdb

El sistema sigue funcionando → RAID 1 correcto.

Pruebas de rendimiento

Se midió velocidad de escritura usando dd.

Comando usado

dd if=/dev/zero of=/mnt/raidX/test.img bs=1G count=1 oflag=direct

Para lectura:

dd if=/mnt/raidX/test.img of=/dev/null bs=1G

(X = raid0 o raid1)

Interpretación

RAID 0 → mucho más rápido.

RAID 1 → más lento por duplicación.

Análisis y comparación

Rendimiento

RAID 0

Muy alta velocidad
Mejor uso de recursos

Sin redundancia

Razón: datos distribuidos entre discos.

RAID 1

Alta seguridad
Escritura más lenta
Usa doble almacenamiento

Razón: duplicación de datos.

Tolerancia a fallos

RAID

Tolerancia

RAID 0

Ninguna

RAID 1

Alta

RAID 0

Si un disco falla → se pierden todos los datos.

RAID 1

Puede fallar un disco sin pérdida.

Sistema sigue funcionando.

¿Cuándo usar cada tipo de RAID?

RAID 0 recomendado para

Procesamiento de video.

Edición multimedia.

Sistemas temporales.

Aplicaciones que requieren alta velocidad.

Datos no críticos.

Prioriza rendimiento sobre seguridad.

RAID 1 recomendado para

Servidores web.

Bases de datos.

Sistemas críticos.

Sistemas empresariales.

Almacenamiento importante.

Prioriza seguridad y disponibilidad.

Impacto en fiabilidad y rendimiento

RAID 0

Máximo rendimiento.

Mínima fiabilidad.

Riesgo alto de pérdida total.

RAID 1

Alta fiabilidad.

Rendimiento moderado.

Protección contra fallos.

Conclusión

RAID 0 mejora significativamente la velocidad pero no protege datos.

RAID 1 reduce rendimiento pero ofrece alta seguridad.

La elección depende de si se prioriza rendimiento o confiabilidad.
